# Dynamic Queries

In scenarios such as drag-and-drop report platforms, table names, column names, and query structures are dynamic and completely unknown at compile time, and it is frequently necessary to generate complex queries with multiple levels of subqueries, sometimes thousands of lines long. Traditional static ORMs and XML-template approaches represented by MyBatis cannot handle dynamic SQL construction in such scenarios. In practice, we are usually left with only two options: error-prone string concatenation, or integrating a heavyweight database kernel front end such as Calcite.

For such scenarios, sqala provides a brand-new solution: a DSL designed specifically for dynamic query construction. The dynamic builder relaxes some of the type-safety checks of [static queries](./query.md), but internally reuses sqala's underlying infrastructure such as the SQL syntax tree, so it still provides safe SQL escaping and guarantees that the generated SQL is syntactically correct. Its calling style is neither as error-prone as string concatenation nor as cumbersome as manually assembling a syntax tree.

Note that dynamic query construction is completely different from [static queries](./query.md). To tell the two scenarios apart, sqala adopts a completely different DSL style, which both fits the use case better and serves as a visual distinction.

Import the dynamic query builder with `import sqala.dynamic.dsl.*`.

The dynamic query builder is still **side-effect free**: each method call produces a new query instead of modifying the previous one.

## Building Queries

The `select` method creates a query. Its arguments are usually several query columns created with methods such as `column` and `value`:

```scala
val query =
    select(column("a", "x"), column("b", "y"))
```

Tables are passed in through the `from` method. Its arguments are usually several tables created with the `table` method:

```scala
val query =
    select(column("a", "x"))
        .from(table("a"), table("b"))
```

Table names in dynamic queries are passed as strings, so they can come from external input; sqala escapes them safely:

```scala
val tableNames = List("a", "b")

val tables = tableNames.map(n => table(n))

val query =
    select(column("a", "x"))
        .from(tables)
```

The `as` method assigns an alias to a table or expression:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a").as("t1"), table("b").as("t2"))
```

Both `select` and `from` can be called multiple times; successive calls are concatenated in order.

## Generating SQL

The `sql` method generates a SQL string. Its arguments are the dialect and the escaping mode (see [Database Interaction](./database.md)):

```scala
import sqala.dialect.PostgresqlDialect

val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))

val sql = query.sql(PostgresqlDialect, true)
```

## Getting the Query Tree

In dynamic construction scenarios, you often need to optimize or transform the generated SQL, but such work cannot be done at the SQL string level. In that case, use the `ast` method to inspect the query syntax tree generated by sqala. If you have knowledge of compilers and database kernels, you can consult the relevant definitions in the `sqala.ast` package and perform query optimization or transformation on the syntax tree generated by sqala:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))

val queryTree: sqala.ast.statement.SqlQuery = query.ast
```

Tables and expressions also support the `ast` method:

```scala
val t = table("a")
val tableTree: sqala.ast.table.SqlTable = t.ast

val e = column("c") === value(1)
val exprTree: sqala.ast.expr.SqlExpr = e.ast
```

After transforming the query tree, you can generate SQL like this:

```scala
import sqala.dialect.PostgresqlDialect

val printer = PostgresqlDialect.printer(standardEscapeStrings)
// Or methods such as printTable and printExpr; see the relevant definitions in sqala.printer.StandardSqlPrinter
printer.printQuery(queryTree)
val sql = printer.sql
```

Here `standardEscapeStrings` is a `Boolean` that determines how string literals inlined into the SQL text are escaped, consistent with the `JdbcContext` constructor parameter of the same name. See [Database Interaction](./database.md) for details.

## Parsing SQL Snippets

Besides building dynamic queries with the DSL, you can also hand a SQL snippet to sqala's built-in parser to produce an expression:

```scala
val query =
    select(unsafeExpr("""lower("u"."name") || '!'""").as("name"))
        .from(table("user").as("u"))
```

`unsafeExpr` only validates SQL syntax; it performs no semantic or type checking, and does not verify whether the tables, columns, or functions exist. **As the name suggests, this method is "unsafe"**: the input should be a trusted SQL snippet, and user input must never be concatenated directly, otherwise SQL injection risks remain. When you need to include user values, use `value(...)` or the normal DSL.

## Filtering

The `where` method takes an expression to filter data. Values are usually created with `value`, and expressions from multiple calls are concatenated with `AND`:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .where(column("a", "x") === value(1))
```

The right-hand side of operators such as `===` can also be another column:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .where(column("a", "x") === column("a", "y"))
```

Most rules for comparison operations and functions are the same as those of [static expressions](./expr.md) in static queries; conditional expressions, however, are specialized for dynamic scenarios: the `caseWhen` method takes several condition-and-result pairs, and `otherwise` finally specifies the default value:

```scala
val e =
    caseWhen(
        (column("a") === value(1), value(1)),
        (column("a") === value(2), value(2))
    ).otherwise(value(3))
```

The generated SQL is:

```sql
CASE WHEN "a" = 1 THEN 1 WHEN "a" = 2 THEN 2 ELSE 3 END
```

## Sorting

The `orderBy` method takes several sort rules (or a `List` of sort rules) to build the sorting; multiple calls are concatenated in order:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .where(column("a", "x") === column("a", "y"))
        .orderBy(column("a", "x").asc, column("a", "y").desc)
```

The sort rules are the same as those in [static queries](./query.md).

## Grouping

The `groupBy` method takes several expressions (or a `List` of expressions) to build the grouping; multiple calls are concatenated in order:

```scala
val query =
    select(count().as("c"))
        .from(table("a"))
        .where(column("a", "x") === column("a", "y"))
        .groupBy(column("a", "x"), column("a", "y"))
```

The `having` method for filtering after grouping works much like `where` and will not be covered here.

## Limiting Results

The `limit` and `offset` methods limit the result set:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .limit(10)
        .offset(10)
```

## Joining Tables

`join` and `on` generate joins:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(
            table("a").join(table("b")).on(column("a", "x") === column("b", "x"))
        )
```

The supported join types are the same as those of [static query joins](./query-join.md).

## Subqueries

The `subquery` method generates a subquery expression:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .where(
            column("a", "x") ===
                subquery(select(count().as("c")).from(table("b")))
        )
```

Pass a subquery to the `table` method and give the returned `SubqueryTable` an alias with `as` to generate a subquery table:

```scala
val query =
    select(count().as("c"))
        .from(
            table(
                select(count().as("c"))
                    .from(table("a"))
            ).as("t1")
        )
```

`any`, `all`, and `exists` generate quantified subqueries:

```scala
val query =
    select(column("a", "x").as("col1"))
        .from(table("a"))
        .where(
            column("a", "x") ===
                any(select(column("x").as("x")).from(table("b")))
        )
```

## Set Operations

Methods such as `union` perform set operations:

```scala
val q1 = select(column("x").as("x")).from(table("a"))
val q2 = select(column("x").as("x")).from(table("b"))
val query = q1.union(q2)
```

The supported set operations are the same as those of [static set operations](./query-set.md).
